## 公共约束（所有轨道适用）

1. 安全底线：不得为通过校验删除条件、补造假设或修改所求；正确拒绝优于错误放行。
2. 不改 `backend/app/settings.py` 的流程默认值；不动 review-only 与 `checkable=False` 路径；不碰自动判分门槛。
3. 模型保持 qwen3-vl:2b-instruct-q4_K_M 与既有调用参数约定；本清单没有任务授权修改采样参数。
4. 单元测试不调用真实模型。真实模型评测统一由冷题验证轮串行执行，各轨道不得自行运行新题或冷题。
5. 修复流程：先写指定失败用例并确认失败 → 最小实现 → 通过对应测试 → 在开发集（已晋升题 + 4 个人工样本）复测。开发集通过不是切换默认流程的依据。
6. 本目录不是 Git 仓库：各轨道严格遵守文末文件所有权，禁止越界修改；需要其他轨道配合的改动写入集成轮清单。
7. 交付时更新 `verify/general-understanding/progress.md` 或新建专项报告；失败样本与运行目录不覆盖。

## 优先级定义

- **P0**：直接对应已观察的冷题失败，或存在静默错答风险；范围明确、实现风险低。
- **P1**：防回归的校验加固与测量基础设施；不直接增加可解题数，但决定改进能否被证明。
- **P2**：能力扩展与结构性工作；依赖 P0/P1 落地或需要集成协调。

## 轨道 A：评测工具（P1）

### A1 run.py 支持图片输入

- 问题：评测入口只传 `{'text': case['text']}`（`run.py:37`），无法评测图片识别；本轮 26 题全部为文字转写，"识别准确性"这一 P0 主张尚未被任何冷题检验。
- 方向：corpus 条目增加可选 image 字段指向本地图片；run.py 以临时 lab 目录方式放置 previews/analysis 图片并构造 source_pages 与 lab_id 调用 understand。staged 走 analysis 原图、legacy 走 previews（1400px 缩放），两模式都要能测。PDF 若现有上传链路支持则一并覆盖，不支持则在报告中标注缺口，不自建 PDF 解析。
- 验收：含图 case 能以 staged 与 legacy 两模式运行；运行目录照常保存题集快照、代码摘要与完整原始响应。

### A2 图片预算预检（只测量，不改代码）

- 问题：staged 使用原分辨率分析图（`extract.py:382-392` 保存缩放前原图），`request_json` 按 `(w/14)×(h/14)` 估算 token（`staged_understanding.py:343-346`）。一张 3000×4000 手机照片估算约 6 万 token，未到模型即被 32k 预算门拒绝；该估算比 Qwen3-VL 实际 patch 消耗保守约 5 倍。
- 方向：准备 3–5 张不同来源与分辨率的真实图片（手机直拍、扫描、截图），分别走 staged，记录每张在预算门、模型调用、识别结果哪一步失败或成功，输出分辨率—结果对照表。
- 验收：得出明确结论——哪些分辨率能进入模型、被拒的统一报哪条错误；该结论决定 C8 的修复方向，以及"局部区域识别"是否必须前置。

### A3 事实级 precision/recall 脚本

- 问题：corpus 每题已存"必要信息检查点"，但事实提取质量靠人工核对（expanded/REPORT.md 中"漏列区间、序列或初态，甚至有多余项"均为肉眼发现）。
- 方向：新脚本读取运行目录 results.json 中 `agent_understanding.conditions`，对照检查点自动计算每题事实命中、遗漏、多余，输出分题与汇总表。
- 验收：对既有 runs 目录回放可产出统计；能区分"解题成功但事实有损"与"事实完整"两类。

### A4 运行汇总与波动报告

- 问题：分项统计目前手工制表；计划第四章要求"困难案例重复 3 次报告波动"，从未执行。
- 方向：汇总脚本按以下维度分类计数并分学科报告：计算正确、计算错误、正确拒绝（理由正确）、正确拒绝（理由错误）、过度拒绝、错误放行、映射失败。"理由对错"依据 unsupported_reason 与 failure_stage 首次人工标注后由脚本复用。支持同一 corpus 多次运行合并，报告波动与不一致项。
- 验收：新冷题轮跑完即自动产出全维度报告；冻结集双跑的差异项被列出。

## 轨道 B：408 内核能力（P2）

三项都是确定性模拟扩展，属内核缺口而非理解缺口。staged 侧的对应改动（拒绝规则移除、事实编译器扩展）一律写入集成轮清单，本轨道不改 staged_understanding.py。

### B1 堆逐个插入建堆

- 问题：`heap.py` 仅支持堆顶删除回放；408 真题"逐个插入关键字序列建堆"当前只能拒绝。
- 方向：heap 内核增加按序列逐个插入（上滤）模式，输出每步数组与最终堆；`kernel_models.py` 的 heap 任务增加插入模式字段与说明。
- 验收：真题插入建堆样本逐步结果与人工参考一致；既有堆删除测试全部通过；新字段校验含缺序列、空序列、堆类型缺失等失败用例。

### B2 非空初态页面置换

- 问题：内核仅支持空初态；staged 侧 `validate_page_model` 检测到非空初态即阻塞（行为正确，根因是内核不支持）。
- 方向：page_replace 任务增加可选 initial_frames 字段；内核从给定初态开始回放 FIFO/LRU/OPT；"初始为空"与"非空"语义不得混淆。
- 验收：非空初态真题得到正确缺页数与逐步状态；空初态路径行为完全不变；初态页数大于物理块数等非法输入被明确拒绝。

### B3 计数类任务

- 问题：堆关键字比较次数、折半查找最坏比较次数无任务支持。
- 方向：折半查找最坏比较次数为确定性公式，但依赖实现版本（区间取整方式），需先文档化采用的教材实现再实现；堆比较计数需先明确上滤/下沉的比较定义。实现版本有歧义时在结果说明中显式标注假设或拒绝，不得默认某一种教材。
- 验收：对应真题样本结果正确；实现假设显式出现在结果说明中。

## 轨道 C：staged 核心（P0+P1，内部串行）

### C1 路由表补齐与任务冲突消解（P0）

- 问题：`candidate_tasks` 的 rules（`staged_understanding.py:36-43`）不含 higher_derivative 等任务；"第五阶导数"命中 `'导数'` 关键词进入 derivative（无 order 字段），必然映射失败。更危险的分支：读题未把阶数提为事实时，绑定校验全部通过，内核静默算出一阶导数——错误放行，仅 review-only 兜底。同类冲突：含等式约束的极值题命中 `'极值'` 进入 optimization（无 constraint 字段）。
- 方向：rules 增加 higher_derivative（"高阶导数"、"第N阶导数"模式）、constrained_extrema（约束词+极值）等条目；具体任务关键词优先于宽泛关键词；每条新路由配"应进其他任务"的反例测试。
- 验收：math24-14 类样本路由 higher_derivative 且 order=5、point=1；"求导数/切线"仍进 derivative；含等式约束极值题进 constrained_extrema；无关键词命中的 fallback 行为不变。

### C3 高频任务 few-shot 建模示例（P0）

- 问题：有示例的任务（double_integral、page_replace，`staged_understanding.py:451-465`）全部通过；无示例的 ode 死在 initial_conditions 数组格式（math24-13 的"尚未映射的条件：c2"即初值 y(1)=0 未进字段）。2B 模型对字段格式的依赖远高于对字段标签的依赖。
- 方向：为 ode、higher_derivative、optimization 各配一个最小示例，只教字段格式；示例数值与真实题不同，防逐字复制。作为独立假设在开发集做有无示例对照并记录结果。
- 验收：math24-13 类样本初值进入 initial_conditions 并绑定；A/B 对照写入报告；既有示例路径不回退。

### C4 表达式字段守卫（P0，D1 的服务端配套）

- 问题：math24-12 把整个 `f(x,y)=...` 定义放进 expression；`_validate` 对 optimization 的 expression 只查字符串长度，含 `=` 通过校验，死在内核解析阶段。
- 方向：expression、integrand、term 等纯表达式字段含 `=` 时阻塞（合法含等号字段 equation、region_text、initial_conditions、constraint、implicit_expression 除外），错误信息指向"函数定义需拆出右侧表达式"。
- 验收：含 `=` 的 expression 被拦截且信息可操作；合法字段（ode 的 equation 等）不误伤；D1 落地后 math24-12 类样本 expression 为纯右侧表达式。

### C2 目标动作分类层（P0）

- 问题：概念/性质题以错误理由被拒。40821-27（哪些事件可能引起进程调度程序执行）在当前代码下仍被 `'进程调度'`/`'时间片'` 路由到 cpu_schedule（单任务，不触发路由调用）；`unsupported_boundary` 的正则（`staged_understanding.py:69`）不匹配该题原文，最终以"名称须为不重复的短节点或进程名"拒绝——结果安全、理由错误。该函数已积累 13 条正则补丁，属"负空间"建模：每道失败题补一条规则。
- 方向：新增 `goal_actions.py`，路由前先分类目标动作（数值计算、模拟执行、计数、概念辨析、证明、性质判断）；概念辨析、证明、性质判断直接以 task_support 拒绝并给出正确理由；把 `unsupported_boundary` 现有规则迁入该层并按动作归类。分类规则保持保守：判不出的归数值计算/模拟，走既有路由，不新增误拒。
- 验收：40821-27、40822-3（中序相邻关系）、调度概念题、最短路径性质题均以概念/性质类理由拒绝（failure_stage=task_support）；13 条既有规则的全部既有测试不回退；否定语境过滤（"不需要|不用|无需…"）的既有反例测试通过。

### C5 绑定值怀疑检查（P1）

- 问题：`validate_bindings`（`staged_understanding.py:140-150`）只查字段存在、ID 合法、全覆盖；模型声称的绑定可以是错的——给 `expression="x^2"` 绑上值为 `"x^3"` 的事实可通过全部校验。仅 page_replace 有值核对（validate_page_model）。
- 方向：新增不对称检查：字段值与全部绑定事实的 presentation-key 均不相等时，标记"派生/待核对"（进入 limitations 与结果展示），不静默通过。这是设计文档"区分直接提取与待验证推导"的落地。合法派生（LaTeX→ASCII、中文数字→阿拉伯数字）不误伤；不确定时标记而非阻塞。
- 验收：构造"绑错 ID+值不符"的单测样本被标记；既有全部开发集样本无误伤，或误伤项均有正当理由并记录。

### C6 目标侧覆盖（P1）

- 问题：事实→模型方向有结构化检查；"所求"→任务方向仅靠 `account_facts` 三个任务的精确短语匹配（`staged_understanding.py:88-105`，如 `value in ('二重积分','计算二重积分','求二重积分')`），换一种说法即无人核对。C1 中"五阶算成一阶"的风险根源在此。
- 方向：所求关键信息（阶数、目标量、通解/特解）与所选任务字段核对；缺阶数或阶数与目标不符时阻塞；account_facts 的精确匹配集合改为任务定义中的声明式描述（先做最小版，完整版归集成轮 TaskSpec）。
- 验收：错误注入测试通过——目标为第五阶而 order 缺失或为 1 时阻塞；特解问题映射成无初值通解时阻塞或标记；正常路径无误伤。

### C7 链式不等式与 uncertainty 分级（P1，两项小改）

- 链式不等式：`validate_explicit_constraints` 的原子模式（`staged_understanding.py:320-329`）不接受 `0<x<1`，此类常见写法逃逸检查。拆解链式不等式逐段核对；拆不开的保留待核对，不得跳过。
- uncertainty 分级：`staged_understanding.py:410` 读题阶段产生任何 uncertainty 即阻断全部建模；设计文档第五章要求区分"影响答案的歧义"与"不影响的小疑点"。按"是否关联已绑定事实/目标"保守分级，非阻塞项保留说明不阻断；无法判定时保持阻塞（宁可过度拒绝）。
- 验收：`0<x<1` 事实被检查，且 `x<1` vs `x<10`/`x<1+y` 既有反例测试通过；无关小疑点不再拦下可解题（构造单测）；关键缺条件仍阻塞。

### C8 图片预算修复（P1，依赖 A2 结论）

- 依据 A2 的分辨率—结果对照表三选一：校准 token 估算系数；或加入保真降采样策略（如限制最长边）；或结论为"必须局部裁剪识别"则本项转为设计方案、不动代码。
