# 本地题意理解 Agent 接入设计

## 目标与边界

学生上传题目，看到题意、已知条件、不确定项、内核交接方案四部分；支持的题目由现有内核计算、复核并生成可调参数和过程轨迹。Agent 仅提出候选，不宣布正确、不生成可执行代码、不代替内核计算。保留现有支持范围，不能支持时明确说明原因。

## 方案选择

建议新增实验室专用 Ollama 适配器，复用现有 ai-solve API、任务目录、子进程计算和交互模型挂载。与修改通用 PPT AI 客户端相比，这样不会改变其他功能的模型行为；引入完整 Agent 框架则增加本次无需的依赖和状态管理。此方案为待用户确认的推荐方案。

## 数据流

1. 上传仍经过已有鉴权、文件校验和预览落盘。OCR 作为辅助材料；对应题目的原图或 PDF 预览页同时传给 Ollama。只从当前实验室已登记的来源键读取图片，不接受模型或前端提供的任意本机路径。多题页面需明确题目对应关系，不能静默漏页或截断。
2. 使用已安装的 qwen3-vl:2b-instruct-q4_K_M，地址从后端配置读取，默认本机 11434；不回退到付费 API。Ollama 不可用时显示可操作错误，不伪造结果。
3. Agent 输出结构化契约：题干和小问、图表关系和所求；条件列表；疑点列表；候选任务、声明式输入或不支持原因。条件有 ID、类型、值、单位、原文摘录、来源页键；图片区域采用归一化 bbox，无法定位时标为未定位，不能编造精确坐标。
4. 服务端检查结构、来源引用、坐标范围、任务白名单和输入预算；最多一次格式修复，失败即明确返回失败。原材料与模型输出均是不可信数据。
5. 缺少必需条件或模型明确指出关键歧义时，保留四部分输出并请求局部补充。仅有通用“原图尚未确认”标记时可以试算，但显示“模型待核对”，不能标记原题答案正确，也不能自动判分。
6. 任务和条件交现有 run_kernel；仅采纳内核返回的结果、检查和交互模型。区分题意确认、模型计算成功、回验通过；模型回验不等于已证明模型忠实覆盖原题。
7. 学生修改参数后继续走现有内核和轨迹流程。前端始终展示题意理解四部分、来源以及内核状态；不支持题型不显示无关教学示例为本题结果。

## 兼容与配置

保留已存实验室文档的读取，新增字段可选；新结果明确标记来源为本地理解 Agent。AI 结果缓存需包含模型、契约版本、原文、来源内容标识及确认状态，避免换图、换模型后复用旧结果。本地启动流程检查 Ollama 状态；不自动下载模型或暴露公网端口。

## 验证

- 自动测试来源越权、无效 JSON、截断、无效任务、缺条件、不支持题型与有限修复。
- 验证模型无法用自报答案、检查状态或轨迹覆盖内核结果。
- 使用桌面 1.png 做端到端测试：原图提取两个约束及被积函数，正确建立区域后由内核独立得到 71/210；模型建错时必须诚实记录失败，不能按样题写特判。
- 验证待确认状态可展示试算但不可自动判分、局部确认后状态更新、调参数后重算与轨迹展示。
- 运行相关后端测试、前端检查并使用浏览器检查实际上传流程。

## 风险

2B 模型已有独立解题重复失败记录，本次只训练外的接入和流程约束，不承诺任意陌生题均可建模；复杂区域等超出现有内核能力时应停止并说明。先用真实测试评价接入效果，再决定模型升级或微调。
