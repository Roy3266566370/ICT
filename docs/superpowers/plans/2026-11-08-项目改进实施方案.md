### I04 新增可提交的微实验学习单〔P1，本轮唯一重点新增功能，前后端〕

#### I04-A 最小产品范围与教学案例

学习流程固定为：**学习目标→锁定预测→完成2—3步操作→查看确定性验证→回答迁移题→保存/导出学习单**。

首版使用登记过的学习单模板，由创建者选择、核对后使用；不要求模型自由生成任意题目或评分规则。模板必须绑定真实来源和已编译节点，教学补充条件另行标记。

| 场景 | 任务与示例 | 原有能力复用 |
| --- | --- | --- |
| 线性代数：特征方向 | 预测向量是否保持方向，比较两个向量，再判断新向量。标准测试例 A=[[2,1],[1,2]]：v=(1,1) 对应 Av=(3,3)；v=(1,0) 对应 (2,1)；迁移 v=(1,-1) 对应 (1,-1) | matrix.transform、特征方向讲解、教学向量探针、来源定位与 practice 分支 |
| 最优化：学习率与收敛 | 同一初值比较不同学习率，再预测另一学习率。标准测试例 f(x)=x²、x0=2：η=0.1 的 x1=1.6；η=1.1 的 x1=-2.4，后续幅度增大；η=0.5 的 x1=0 | optimization.gradient、轨迹与停止原因、参数控件及已登记求值器 |

上述数值仅为标准测试例，不得强行套入任意课件。真实材料的矩阵、目标函数与初值来自其来源；不足时创建者明确补充，页面标明教学条件。首版只允许绑定已有算子支持的场景，不为凑案例新增任意代码执行。

首版契约：

| 对象 | 必需信息与约束 |
| --- | --- |
| `MicroExperimentDefinition` | `contract_version`、`definition_id`、`version`、`operator_id`、标题、学习目标、来源、必要 bindings、预测题、2—3个操作步骤、迁移题、核验规则编号 |
| `MicroExperimentAttempt` | `attempt_id`、定义编号/版本、已有 `LearningContext`、`phase`、预测记录、最多3个检查点、学生解释、迁移答案、服务端核验结果、revision及时间 |

| 内容限制 | 解释与迁移文字各≤1000字符；单个 attempt 序列化≤64KiB，过大明确拒绝 |

定义为程序登记的版本化教学模板，与当前已编译来源绑定；attempt 存入新建 `kind=practice` 分支的 `learning_json.micro_experiment`。保留已有 node/page/context metadata；不能将相同 metadata 放入 baseline。更新使用分支 revision 条件更新，并在受校验的 metadata 中保留有限 operation_id 记录，满足重放幂等。

新增私有路由统一前缀 `/api/v1/materials/{material_id}/ai-learning/micro-experiments`：

- `GET /definitions?node_id=...`：只读返回当前节点可用的定义及适用/缺失条件。
- `POST /attempts`：接收定义编号/版本、现有 `LearningContext`、`operation_id`，创建独立 practice attempt，返回 201。
- `GET /attempts/{attempt_id}`：只读恢复本人学习进度。
- `PATCH /attempts/{attempt_id}`：接收 `expected_revision`、`operation_id`、当前 `LearningContext` 与单个动作；动作限 `lock_prediction`、`record_checkpoint`、`submit_transfer`。服务端校验状态和重算。
- `GET /attempts/{attempt_id}/report`：只读返回冻结的私有学习单 JSON，用于下载；不调用模型，不自动变成公开链接。

冲突沿用 409；缺失/无效输入沿用已有校验错误。attempt ID 为新 practice 分支 ID，归属查询同时限制账号/会话、material 与 bundle，不能仅凭 ID 读取。

路由登记修改 `E:/代码/ICT/backend/app/api/registry.py`，沿用该文件当前登记方式；定义契约与前后端类型同时修改。新报告是独立 `micro-experiment.1` 产物，首版不将私有 attempt 塞入现有公开 `ppt-learning.1` 快照，也不隐式改变 `.xsproj` 格式。

| 阶段 | 时间建议 | 工作与交付 |

| A | 第1—5天 | 测试 T01/T02 先行；I01/I02 修复最影响核对和首次使用的问题 |
