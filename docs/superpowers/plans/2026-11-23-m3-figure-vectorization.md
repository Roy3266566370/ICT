# M3 万象活页图示矢量化实施计划

> 分阶段实施，每个任务独立验收。工期按一人 10 个工作日估算，第 5 个工作日做里程碑评审。

## M0 证据与 M3 决策

基准图为 900 × 485 px 的换基图，人工标注 13 个对象。验收要求每个对象误差严格小于图宽的 3%，因此这张图需要至少 12/13 个对象达标。

| M0 方案 | 可评分对象 | 位置达标 | 单次调用耗时 |
| --- | ---: | ---: | ---: |
| 原图，直接输出像素端点 | 2/13 | 0/13 | 10.12 秒 |
| 原图，归一化具名字段 | 13/13 | 1/13 | 60.00 秒 |
| 网格叠图，归一化具名字段 | 13/13 | 3/13 | 59.92 秒 |

后两组并行发起，每种配置各一次。结果足以说明当前响应的格式和位置误差问题，延迟分布仍待顺序复测。数据来自本机配置的远端视觉服务。 [M0 实测报告](../../../verify/walkthrough-2026-11-23/report.md)

**首发路径采用原生几何优先、像素几何补足、视觉模型辅助匹配。** 原生或像素候选提供最终坐标，OCR 提供文字及框。Qwen 在条件允许时补充对象分类、标签归属和校对候选。没有坐标证据的视觉提议留在校对态，用户调整确认后方可应用。单独继续调整坐标 Prompt 的收益以探针结果评估。

现有上传任务在 `routes_jobs.py` 中调用 `prepare_source_vectors()`。它已经具备原生线段、像素箭头、清底和页级写入保护，视觉仍随上传触发。PPTX 解析器已经遍历组合形状，`documents/importer.py` 当前把整个组呈为单个节点。M3 在这两个接入点扩展，从已有 `SceneDocument` 和 `VectorLine` 继承操作及持久化。

## 任务 1 · 评分复用与像素探针（第 1–2 天）

- [ ] 将 M0 评分入口复用为离线验收脚本，保留 13 个对象 ID、坐标、文字和图宽。箭头取方向敏感的端点最大误差，轴和虚线允许交换端点，文字同时校验内容和文字框中心。缺失、重复匹配、错误类型或错误文本记失败，同时单列多余对象。
- [ ] 建立四个额外验收样本。使用已有 `basis-compressed.jpg` 验证压缩干扰，准备含嵌套组、旋转和翻转的 PPTX 验证原生几何，准备一张**非双子图结构的正例位图**（如单坐标系向量分解或几何示意图）防止像素检测对换基图过拟合，再准备一张相似但无向量关系的负例测试误识别。验收标注在调参前固定。
- [ ] 在 `documents/auto_vectors.py` 复用 `pixel_arrow_candidates()`，补轴线、分段虚线和 OCR 标签框。用轴线交点、箭头尖端及邻近文字拟合每个子图的坐标系，按源图像素校验吸附前后的误差，并自动分区处理单/多原点子图（避免写死双原点魔数）。
- [ ] 顺序测量冷缓存、暖缓存与禁用模型三种场景，每种至少三轮。保存每对象误差、识别覆盖率、额外对象、各阶段耗时和调用次数。先用原图做选型，压缩图、单子图正例与负例用于检查泛化。

通过条件为换基原图达到 12/13 个对象且没有多余可应用对象。目标未达时，按对象类型记录缺口，将欠证据的对象转为校对候选，第 5 天按同一标注复测。

## 任务 2 · FigureScene 与 PPTX 原生提取（第 2–4 天）

- [ ] 在后端增加 `FigureScene v1` 校验，在前端补对应类型。每个子图保存独立坐标系，明确裁图像素、数学坐标与页面坐标的转换。对象覆盖轴、线段、矢量、折线、虚线和文字，逐项留存 `native / pixel / vision / user_confirmed`、证据与拒收原因。关系只保存声明和引用，为 M4 预留数据。
- [ ] 在 `documents/importer.py` 和 `auto_vectors.py` 扩展组合形状遍历（现有 `_walk_shapes` 仅做轴对齐平移缩放，不含旋转与翻转）：改为逐层累乘 **2D 齐次仿射矩阵**（累计嵌套组的缩放、偏移、`rot` 旋转与 `flipH`/`flipV` 翻转），再作用到线段的原生起终点，保留箭头方向、线型、主题色、文字样式和层级。确认组内可替换的全部内容后切换图层；含不支持对象的组保留原渲染，避免对象重复或缺失。
- [ ] 提供 `FigureScene → SceneNode` 适配器，复用 `VectorLine` 和 `DocumentController`。对重复 ID、无效引用、退化线、越界坐标和不可信标签做逐项校验。只有直接从 PPTX 读取并校验过的对象标成 `native`。
- [ ] 扩展 `backend/tests/test_auto_vectors.py`，断言嵌套 PPTX（含旋转/翻转）的像素端点、层级、方向、样式和来源。覆盖部分可解析的组及既有文档加载。

通过条件为原生 PPTX 固定样例能完整保留图示，目标对象全部标为 `native`，识别链路发出零视觉请求。用户可在编辑器拖曳端点和编辑线型、颜色及线长。

## 任务 3 · 按需识别、缓存与视觉开关（第 4–7 天）

- [ ] 拆分 `prepare_source_vectors()`：上传阶段**仅保留原生矢量提取**，移除上传时的位图像素识别与视觉调用，避免覆盖原图。实现 `POST /materials/{id}/pages/{n}/figures/{element_id}/vectorize`，复用材料归属及编辑权限；按需接口统一从页面节点对应的已渲染图片资产读取裁图，**不强依赖 `source.pptx` 存在**（同时兼容 PPTX 内嵌图、PDF 页图与直接上传的图片）。生成返回预览，应用时再次核对元素内容和文档修订。
- [ ] 缓存至少覆盖同材料同图的重复点击。键包含素材内容哈希、裁图与 OCR 证据哈希及实现版本。同键复用进行中的请求结果，失败可显式重试。耗时调用在文档写锁外，应用沿用版本检查及编辑器撤销语义。
- [ ] 复用 `LivingVisionClient`，采用**两段式体验**避免视觉 60 秒长尾延迟直接撞上 25 秒超时：本地像素检测 + OCR（`< 2s`）先立即可见可校对；视觉增强阶段仅向模型传裁图、候选编号、候选 geometry 和 OCR 框，要求返回极简的对象分类、标签关联与证据引用 JSON（收紧 `max_output_tokens` 至 500–800），增量补齐预览。只接受可与已知候选或 OCR 标签匹配的建议，几何验证失败给出逐项原因；视觉超时后保留已通过的像素与 OCR 结果及手动工具。
- [ ] 在材料权限和保留期内保存诊断，记录阶段、HTTP 状态、耗时、原始响应和逐条拒收原因，凭证与请求鉴权头不进入记录。加上权限、缓存命中、模型超时、无模型、过期预览和并发点击的 API 回归。

第 5 天根据探针决定视觉分支的交付范围。像素路径通过时，可以独立交付原生和像素识别，视觉仍按证据验收。像素精度不足时，按失败对象类型继续补强，并将当前输出限定为可校对的预览。

## 任务 4 · 双底图与端到端验收（第 7–10 天）

- [ ] 复用 `auto_vectors.py` 的清底和现有编辑器图层。校对态显示半透明原图；编辑与演示态只清除已确认接管的笔画。原图与清底图**落盘为独立 PNG 资产文件**（节点仅存 `cleaned_asset_id` 引用，**不再往 `document.json` 内嵌 base64 `image_data`**，避免拖慢 PATCH 读写）；局部清底失败时保留相关原图区域。通过预览、应用、撤销和刷新验证一致性。
- [ ] 收口上传流程中图片 `steps_*` 和旋转伸缩启发式的默认自动生成，保留手动模板及已保存交互。按对象 ID 统计当前已应用的识别对象，缓存命中和重复应用不重复计数。
- [ ] 在真实浏览器验收原图、压缩图和原生 PPTX。分别记录上传到可编辑、点击到预览两项时延。用真实上传加首次按需识别的连续流程对照 v3 的 25 秒目标。点击指标单独达标时，完整流程仍按实测单独记录。
- [ ] 在有模型和关闭模型的两种配置下重复验收。检查图层覆盖、移动后的重影、部分识别、缓存刷新和手动添加。保存对照截图、误差明细及失败样例。

## 发布口径

| 条件 | 交付口径 |
| --- | --- |
| 原生 PPTX 对象来源、几何和样式通过，位图 12/13 达标且连续流程不超过 25 秒 | 对已验证输入开放自动矢量化预览 |
| 部分对象达标或连续流程超过 25 秒 | 保留原生路径。位图提供候选校对，记录超标项 |
| 无视觉模型、视觉超时或校验失败 | 保留通过的原生和像素结果、原图以及手工添加矢量入口 |
