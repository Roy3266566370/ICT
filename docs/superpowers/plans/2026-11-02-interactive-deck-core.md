# 网页 PPT 核心交互完善 Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 在现有真实 PPT 转换链路上，让公式可观察、调参可撤销与对比、导出的整份网页在离线环境保持交互。

**Architecture:** 保留原页与页序，继续使用受限 iSpec 和同一参数状态。离线文件复用 React 演示运行时及表达式求值器，内联页图、CSS、字体和脚本，不另造简化计算逻辑。

**Tech Stack:** React / TypeScript / SVG / Vite / FastAPI / python-pptx。

**Spec:** 用户要求继续 WorkBuddy 修改；选题文档的“调整条件、逐步运行、比较方案”，修订整改文档的统一状态与断网可交互产物。

## 范围与选择

沿用用户已选的原页演示方式。可选的全新幻灯片编辑器会扩大范围；继续简化版 HTML 会再次丢失图形与计算。采用现有运行时共用方案。此决定为实施判断，不表示用户逐项批准了新增细节。

- 不按文件名或固定页码配置交互，不把示例当用户解析结果。
- 图片推断与人工配置保持明确来源。
- 原件、已有编辑和 WorkBuddy 修复保留。
- 本地无 Git 仓库，直接修改当前授权工作区，不创建虚构提交。

## Review Focus

- 公式定义域错误不能跨断点连线，不能让整页白屏。
- 撤销、重做、恢复快照必须原子更新相关参数，不能污染其他对象。
- 图片识别文本纠正不能把步骤图误替换为零矩阵或删除原交互。
- 离线文件不能请求 API、CDN、字体或页图；所有原页和交互都须保留。
- 保存后导出应使用当前参数，导出内容不得携带会话或本地文件路径。
