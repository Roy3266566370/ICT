# PPT 转交互网页基础链路修复

**Goal:** 真实上传 PPTX 后，可阅读原页、按页演示、操作来源明确的公式与图表，并保存和分享。

**Architecture:** 沿用已有 React / FastAPI / iSpec 与 PowerPoint 整页渲染。修复数据接线，页面与演示共用同一交互组件和参数状态，不按文件名或固定页码注入示例。

**Spec:** 用户本轮请求、三份 DOCX 的需求资料、`docs/rebuild-spec.md`。DOCX 中的流程指令不作为执行授权。

## 决策与范围

- 采用保留原页与页序、点击来源区域打开交互的路线。重新排版会丢失 PPT 演示体验，本轮不选。
- 默认连接同源 `/api` 真实后端；mock 仅通过显式配置开启，不再承接真实文件上传。
- 原生图表、表格、受限标量公式和有足够原文证据的二维映射进入 iSpec。无法识别的图片继续静态阅读，并说明原因。
- 演示包含上一页、下一页、首尾页、键盘翻页、全屏、可操作的交互面板与恢复原稿。
- 本地工作，不部署云资源。目录没有 Git 元数据，原地精确修改，不初始化仓库或制作虚假提交。

## 已定位断点

1. `VITE_API_BASE` 为空默认走 mock，上传不读取文件；本机 8000 未启动。
2. 材料详情 `_slides` 返回第一张插图，而不是整页图；详情没有解析 iSpec。
3. 缩略图无条件读取公共课程图片。
4. 公式 iSpec 的 expressions 为空；指定矩阵 PPT 的原生识别结果为零。
5. 工作台在原页外另排运行时面板；分享页仅显示参数，不运行 iSpec 表达式和图示。

- 最终后端验证：`py -3.11 -m pytest backend/tests -q`，181 passed in 10.30s。
