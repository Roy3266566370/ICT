## 首轮结果（修复前）

六题全部正确分类为 `computer_network` 并标记 `ready`，但答案几乎全是
**通用讲义文本**——解析器没认出真题表述，唯一算出数值的 cn6 还是错的：

| 图 | kind/engine | 原结果 | 问题 |
| --- | --- | --- | --- |
| cn1 | physical / net_physical_v1 | 通用调制概念，无数值 | `_parse_levels` 不认"N相位×M振幅"复合QAM |
| cn2 | sliding_window / net_window_v1 | 通用GBN规则，无数值 | 只认"第N帧丢失"，不认累积确认重传题 |
| cn3 | mac / net_mac_v1 | 通用CSMA/CD规则 | 无"帧长变化→距离变化"路径；"200 000"千分位空格不解析；"传播速度"不在标签表 |
| cn4 | ip / net_ip_v1 | 只算母网：254台 | `/24` 显式前缀使 `子网掩码为.248` 被跳过，没做定长划分 |
| cn5 | transport / net_transport_v1 | 通用TCP规则 | 序号推进只支持单段长度，不认"两段300B+500B" |
| cn6 | tcp_control / net_tcp_v1 | **cwnd=256 MSS（错）** | `timeout_match` 只认"第N个RTT超时"，"cwnd=16KB时发生了超时"被忽略→直接翻倍 |

## 修复的缺陷（全部在 `backend/app/labs/computer_network.py`）

| # | 位置 | 修复内容 |
| --- | --- | --- |
| 1 | `_NUM` | 数字允许千分位空格（`200 000km/s`→200000），要求空格后恰 3 位，不误拼序号串 |
| 2 | `_parse_levels` | 新增"N个相位×M种振幅"复合 QAM 识别 → levels=N·M；允许跨行 |
| 3 | `_eval_sliding_window` | GBN 累积确认路径：`编号为a~b的帧 + 只收到x、y号帧的确认` → 重传 max(ack)+1…b 全部帧，报帧数 |
| 4 | `_eval_mac` | 帧长变化→距离变化：`Δd = ΔL·v/(2R)`，方向随增/减；传播速度标签补"传播速度/信号传播速度"；metrics 兼容 delta 变体 |
| 5 | `_eval_ip` | 显式前缀 + 独立 `子网掩码为X` → 定长划分：new_prefix=掩码前缀，子网数=2^(new−base) |
| 6 | `_eval_transport` | 多段 TCP：`TCP段…N字节…M字节…序列号为S` → 累积确认 S+Σ载荷 |
| 7 | `_eval_tcp_control` | "拥塞窗口为N时发生了超时"→ 先落地 ssthresh=N/2、cwnd=1，再按 RTT 数推进；MSS 支持反序写法"1KB的最大段"；答案附 KB 换算 |

OCR 断行兼容：`编号\n为0～7`、`的确\n认`、`4个相位，\n每个相位` 均可识别。
