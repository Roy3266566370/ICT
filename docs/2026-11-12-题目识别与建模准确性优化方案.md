# 题目识别与建模准确性优化方案

日期：2026-11-12。状态：设计方案，尚未实施或实测。

本文汇总准确性优化方法、采用顺序及后续扩展方式。与[通用流程实施计划](superpowers/plans/2026-11-12-general-understanding-pipeline.md)配套：实施计划负责文件、接口和测试任务，本文负责说明各方法为什么采用、解决什么错误、怎样验证收益。本文不代表已安装新模型或新增题型能力。

## 1. 目标与判断原则

目标是让最终结果忠实回答原题，而不仅是让内核成功返回答案。需要同时提高图片读取准确性、条件完整性、模型忠实性、计算正确性与小问完成度。

每一步本身正确仍不够，还要检查相邻步骤的转换有没有丢失约束、添加假设或改变所求。每个阶段交付“结果、来源依据、未解决问题”，后续只能在其适用范围内继续。

采用“通用流程＋任务专用建模和校验”。先用已有高数与 408 题型验证；物理、电子等通过任务定义和专业适配逐步接入，不强迫所有题目变成同一种公式模板。

方案不承诺任意题目都能自动正确求解。无法读取、无法建模、无法验证分别保留状态；少答一些题与真正提高正确率必须在评测中区分。

## 2. 整体工作流

原始材料 → 整页布局和局部识别 → 来源绑定的题目事实 → 候选任务及声明式模型 → 模型校验 → 内核求解 → 独立结果检查 → 分项答案与验证说明。

逻辑上仍是“理解题目→选择任务并建模→检查模型→调用内核”。图像预处理属于理解阶段，独立结果检查属于内核结果验收，不要求每个方框增加一次模型调用。

默认复用现有本地 Qwen：一次理解，一次建模。局部重识别、路由扩展和修复按疑点触发，共享实施计划规定的总调用预算；对普通清晰题不无条件增加多轮反思。

## 3. 优先采用的方法

| 优先级 | 方法 | 主要处理的错误 | 采用判断 |
| --- | --- | --- | --- |
| P0 | 原图保留、整页布局与原分辨率局部识别 | 指数、下标、小字、表头被缩放丢失 | 当前模型使用预览图，存在明确值得验证的输入瓶颈 |
| P0 | 条件来源绑定、双向覆盖核对 | 漏约束、补假设、答案混入条件、漏小问 | 直接针对题意与模型不一致 |
| P0 | 任务专用 schema 和语义校验 | 混合字段、错误任务、无效条件转换 | 降低 2B 单次处理复杂度，复用现有内核 |
| P1 | 具体错误或反例引导的局部修复 | 同类错误反复出现、整题重写引入新错 | 需要已有可信检查依据；限定次数 |
| P1 | 独立结果检查与错误注入测试 | 错解被接受、检查器形同虚设 | 提高放行结果的可靠性，不直接改善视觉识别 |
| 持续基础 | 真实错误集、合成变体、逐项对照实验 | 不知道错误来源、无法证明优化有效 | 从第一阶段建立并持续更新 |
| 后续 | 多候选、微调、专用识别模型、SMT/证明助手 | 已定位且流程优化不能解决的能力缺口 | 由实测决定，不默认全部叠加 |

以上是工程优先级，不是已经测得的收益大小。

## 4. 图片读取：信息保真和按需重读

### 4.1 推荐流程

1. 保存原始材料，区分题目、补充数据、学生解答和参考答案。
2. 用整页确定题目范围、阅读顺序、跨页续写、图表与正文对应关系。
3. 从原始图片或 PDF 页面生成公式、表格和配图局部；保留整题上下文和裁剪到原页的坐标映射。
4. 普通 OCR、公式 OCR 和视觉模型按内容使用，不要求每块都调用全部引擎。
5. 关键结果分歧时只重读相应区域；无法确认则保留候选并请求局部核对。

不从缩小预览放大来假装恢复细节；不以生成式补图重建缺失符号；图跨区域时保留重叠与整图，避免裁剪切断连接关系。旧材料只有预览时，记录质量限制，不能伪造原图。

### 4.2 按结构读取

| 内容 | 输出结构 | 关键检查 |
| --- | --- | --- |
| 正文 | 题干、段落、小问及来源范围 | 阅读顺序、否定词、限定条件 |
| 公式 | 原始表达与规范化表达 | 上下标、分式范围、根号范围、不等号、定义域 |
| 表格 | 表头、行列、单元格和单位 | 不遗漏空值、不串列、不把表头当数据 |
| 数据结构图 | 节点、边、方向、权重 | 箭头、孤立节点、图例和访问规则 |
| 未来物理/电路图 | 对象、标注、关系与连接 | 方向、接触、端点、极性；未实现专用解析前保留不支持 |

结构恢复必须允许未知，不能用学科常识自动补出原图没有的内容。

## 5. 条件整理：事实账本与双向核对

每条事实保留稳定 ID、类别、原始内容、规范化内容、单位、来源、确认状态和所属小问。原始内容不可被规范化覆盖；例如化简分式后仍需保留分母非零条件。

区分三种内容：原题事实、用户确认、程序验证过的推导。模型提出的推导只是候选，不能直接标为已知事实或已验证。

进行两次覆盖核对：

- 原题→事实：重要公式、数据、限定词、初态、关系和小问是否全部保留。
- 事实↔模型：每个影响求解的事实是否真正被使用；模型额外引入的约束、参数和假设是否有来源。

对应关系不仅检查 ID 是否出现，还要核对实际值和语义。对于无法自动判定的关系保留待核对。来源摘录也需核实，模型自己写了一段“原文”不等于证据。

核对问题按任务生成，如“RR 时间片是否提供”“图是否有向”“是否要求全部解”“是否还有第二小问”。必要时核对调用独立查看原材料，避免只围绕第一次摘要重复确认。

明确缺条件与不影响答案的歧义；前者阻塞正式计算，后者保留说明。若支持展示明确假设下的情景计算，必须标作假设情景，不能冒充原题答案。

## 6. 模型生成：按任务编译，而非自由发挥

采用编译器式转换：题目事实→任务输入→计算模型。每层保存来源映射；规范化与任务转换各有校验。

1. 根据目标和事实筛选少量候选任务；证据不足时允许扩大简短任务目录，不因关键词未命中立即拒绝。
2. 只向建模模型提供选中任务相关字段、类型、要求、适用边界和少量准确示例。
3. schema 约束结构；专用校验检查变量、范围、单位、矩阵维度、初态、图关系与任务规则。
4. 可由现有内核推导的内容交给内核，例如二重积分原始区域的积分限。
5. 所有小问分别记录任务和完成情况；没有实现依赖执行时保留依赖，不用模型猜出的前问答案填后问。

字段定义、提示说明与服务端验证应来自同一任务定义，避免相互矛盾。结构合法只是第一关，不作为语义正确的证明。

## 7. 检查和修复：返回可操作的错误

错误必须包含所属阶段、目标/事实 ID、字段位置、具体原因和允许修复范围。例如：

“事实 C2 要求 x>0，但模型未保留变量范围；x=-2 满足候选方程却违反 C2。”

处理方式：

| 错误 | 返回位置 | 保留与失效规则 |
| --- | --- | --- |
| 关键符号读不清 | 对应局部图 | 确认事实变化后使依赖模型和结果失效 |
| 条件漏提 | 读题结果 | 保留其他已确认事实，重新检查覆盖 |
| 字段类型或约束映射错误 | 对应候选模型 | 不允许修改原题条件来让计算通过 |
| 内核能力不支持 | 能力状态 | 保留题意和已完成小问，说明具体边界 |
| 计算或独立验证失败 | 求解/检查阶段 | 不将失败直接归罪于模型或擅改题目 |

反例搜索只针对已形式化、可信的条件。搜索没找到反例、求解器超时或 unknown 均不等同于证明正确。

## 8. 输出可信度：独立检查和完整性

求解器输出答案及必要证据；检查器依据已确认输入检查，而不是直接接受求解器的“通过”字段。两者尽量不复用同一段关键计算逻辑，避免共同错误。

首批可选证据：

- 不定积分：求导回验及定义域检查。
- 方程/极值：可行性与范围；全部解、全局最优需要另行完整性依据。
- BFS：可达性、父节点、距离和边约束；遍历顺序需要原题规则。
- 页面置换/调度：初态、逐步状态转换、算法规则和统计量。
- 银行家：逐步 Work/Need 核验；一条合法安全序列证明安全，找不到某条序列不自动证明不安全。

分别呈现题意确认状态、模型检查结果、验证方式和小问完成范围。数值交叉检查、确定性规则检查和形式证明分开标记，不折算为未经校准的统一置信度。

## 9. 扩展方式：保留接口，不预建复杂框架

### 9.1 新题型的接入清单

每个任务增加一份明确的能力定义：

1. 任务 ID、版本、学科标签、支持与不支持范围。
2. 输入字段、类型、单位和条件依赖。
3. 事实到字段的映射规则及允许推导。
4. 专业语义校验和缺条件处理。
5. 内核适配、结果结构与检查证据。
6. 正确、缺条件、错误模型、不支持和边界用例。
7. 需要交互展示时再提供前端适配；无专用画布不影响理解结果保存。

先使用项目内静态注册和普通模块，不做动态插件市场或通用工作流引擎。新增任务原则上主要改任务模块，而非在主流程按学科堆叠分支。

### 9.2 新学科怎样扩展

| 示例 | 可复用内容 | 必须新增或验证的内容 |
| --- | --- | --- |
| 一维运动 | 条件来源、变量、方程求解、结果状态 | 单位、正方向、运动阶段与方程适用条件 |
| 直流电阻网络 | 图关系、矩阵求解、来源核对 | 电路拓扑、参考地、极性、器件模型和连接校验 |
| 数字逻辑 | 布尔关系、表格、状态记录 | 位宽、时序、逻辑规则和专用验证 |
| 证明/概念题 | 原题事实、小问、证据与不确定状态 | 对应证明检查或依据核查；不得直接借用数值成功状态 |

通用数据结构允许实体和关系为空，也允许任务专用的类型化扩展字段；扩展字段需有版本和校验，不能变成不受约束的任意字典。新增计算能力仍需开发与测试，不能仅靠增加提示词宣称支持。

### 9.3 新算法或模型怎样替换

识别组件统一返回内容、来源、坐标、候选与错误；建模组件返回声明式模型；校验器返回结构化问题和验证依据。不同组件遵守这些契约即可进行对照替换。

记录模型标识、提示版本、任务版本、识别与校验版本、输入摘要、参数和人工确认。影响结果的版本变化必须使相应缓存失效；事实变化会使所有依赖结果失效。

这保留未来替换 OCR、引入领域模型、LoRA、SMT 或证明检查器的空间，但不要求当前安装这些组件。

## 10. 持续优化：用证据决定保留什么

首批沿用实施计划的 100 个原题组，开发与保留集按原题分组，文字版/裁剪版/整页版不能跨组泄漏。高数和 408 分开报告，再报告整体。

每个失败样本归档原材料、正确事实、阶段输出、错误位置、人工修正及版本，形成可回放的错误集。用户纠正应经过审核再作为训练或评测标注；不能让一次未经核实的纠正自动修改全局规则。保留评测题不进入微调集。

对照顺序：当前基线→局部识别→来源绑定与覆盖检查→专用建模→校验修复→独立结果检查。每次尽量只改一个因素，记录识别准确性、条件 precision/recall、忠实建模率、完成率、错误放行/拒绝率、调用数、P50/P95 耗时。

增加两类测试：

- 错误注入：删除 x>0、翻转有向边、修改初态、漏掉小问，检查对应环节能否发现；同时提供合法近似案例，检查是否过度拦截。
- 已知不变性：更换无语义影响的排版、字号、变量名称或图布局时，核心模型应保持等价；更改真实数值或方向时，相应模型应随之改变。变换须经人工或程序确认确实保留题意。

合成图片用于定位小字、公式、表格和图关系问题，不替代真实材料评测。遇到保留集被反复用于调参时，应新增未见过的评测组。

没有稳定收益的方法不默认开启。准确率不变但降低耗时的方法仍可保留；准确率改善却明显增加延迟的方法可作为按需复核模式。不得仅靠提高拒绝率宣称系统整体更准确。

## 11. 推荐落地顺序

1. 建立基线、事实契约和失败分类，同时统一现有任务字段。
2. 改善图片输入，接入独立读题与来源绑定。
3. 高数和 408 同时接入任务专用建模、双向覆盖和专业校验。
4. 增加错误驱动修复与首批独立结果检查器，核对预算与延迟。
5. 完成保存、确认、缓存、旧文档和多小问状态的回归验收。
6. 用保留集判断启用范围，再按任务接入物理、电子等内容。
7. 若仍存在稳定能力缺口，再比较专用模型、更高精度、更大模型或微调，按收益与资源成本选择。

## 12. 研究依据与适用边界

| 研究 | 借鉴内容 | 本方案的使用边界 |
| --- | --- | --- |
| [MinerU2.5，2025](https://arxiv.org/abs/2509.22186) | 整页布局与原分辨率局部识别分离 | 借鉴输入组织方式，不承诺 Qwen 2B 获得相同效果 |
| [DePlot，2022/2023](https://arxiv.org/abs/2212.10505) | 图表先转换成结构再推理 | 原研究针对图表，不提供电路拓扑识别保证 |
| [Chain-of-Verification，2023](https://arxiv.org/abs/2309.11495) | 形成具体核对问题并独立回答 | 应核对原材料；自我确认不等于独立证明 |
| [PICARD，2021](https://arxiv.org/abs/2109.05093) | 解析约束生成 | 原研究主要是 SQL；本项目借鉴任务结构约束，另做语义校验 |
| [Faithful Chain-of-Thought，2023](https://arxiv.org/abs/2301.13379) | 符号中间表示与确定性执行 | 可追踪执行不保证自然语言翻译无误 |
| [Program Synthesis By Sketching，2008](https://www2.eecs.berkeley.edu/Pubs/TechRpts/2008/EECS-2008-177.html) | 反例引导候选修正 | 依赖可信规格与验证器；本项目采用受限的局部修复 |
| [olmOCR 2，2025](https://arxiv.org/abs/2510.19817) | 具有已知真值的合成文档与可验证测试 | 原模型训练和英文基准收益不能直接外推；先借鉴评测设计 |
| [Self-Consistency，2022/2023](https://arxiv.org/abs/2203.11171) | 多样候选与一致性选择 | 作为后续对照项；一致不证明正确，不能补回丢失信息 |

本文使用前轮已检索的论文资料作方法依据，具体项目方案属于工程判断。当前未执行新流程、训练或真实题集对照测试，尚无准确率提升数值。
