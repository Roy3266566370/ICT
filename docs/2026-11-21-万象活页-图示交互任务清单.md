## 4. 已知边界（P0–P3）

- **P3 准确率范围**：100% 仅适用于上述两个公开样本，衡量节点文字与有向边拓扑。真实课件回归的其余用例主要验证区域提取、裁剪或 OCR，尚未覆盖不同文件格式和复杂课件的流程图准确率。
- **P3 离线范围**：单文件 HTML 为只读快照，支持流程图浏览和单步演示。编辑、重新识别、学情回传、外部嵌入和服务端判分需在线。部署环境需先构建离线运行时。导出图像合计上限为 64 MiB，缺少所需图像时会提示失败。断网打开验收使用桌面 Chromium。

- 图示热区已有 diagram 数据时打开 **React Flow 流程图画布**；无 diagram 时仍是裁剪 + 标签视图，由作者点「识别流程图」按需调用视觉模型。
- PDF 公式区域上传时只留裁剪图；LaTeX 由作者在面板点「识别公式」按需本地 OCR（15s 超时），超时/失败只留裁剪与普通文字，不伪造。
- 公式区域 `expression` 只覆盖自由变量 ⊆ {x,a,b,c} 的一元函数；其他公式只落 formula 块，可发 AI 交互。
- 示意图标签：矢量图/PPTX 走确定性文字层与形状框，位图走 OCR（限额 10/文档）；OCR 标签置信度受原图质量限制。

## 8. 运维说明

**环境变量（`backend/.env`，gitignored）**

| 变量 | 含义 | 默认/示例 |
|---|---|---|
| `LIVING_FIGURE_VISION_PROVIDER` | `siliconflow` 或 `none`（none = 功能禁用，区域保留原图） | `siliconflow` |
| `LIVING_FIGURE_VISION_BASE_URL` | OpenAI 兼容端点 | `https://api.siliconflow.cn/v1` |
| `LIVING_FIGURE_VISION_MODEL` | 视觉模型名（参与 cache_key） | `Qwen/Qwen3-VL-32B-Instruct` |
| `LIVING_FIGURE_VISION_API_KEY` | Key，只进 `Authorization` 头，不出现在任何响应/日志 | `sk-…` |
| `LIVING_FIGURE_VISION_TIMEOUT_S` | 单次视觉调用超时 | `90` |
| `LIVING_FIGURE_MAX_CALLS` | 每文档视觉调用预算（含失败与重试次数） | `12` |

**端点**

- `POST /api/v1/pages/{id}/regions/{rid}/formula-ocr`：本地 LaTeX OCR（15s 子进程超时，不伪造）。
- `POST /api/v1/pages/{id}/regions/{rid}/diagram`：视觉流程图转译。缓存序：`pptx_shapes` 确定性转译 → `cache_key(png+evidence+prompt_version+model)` 命中 → 预算检查 → 调用（可重试错误在剩余预算内自动重试 1 次）→ 校验 + OCR 证据匹配 → confidence<0.3 丢弃。每次尝试先 `vision_calls+1` 落库（`UPDATE … WHERE revision`，并发修改 → 409，错误体带最新 revision）。
- `GET /api/v1/living/ai-status`：文本 LLM + 视觉 profile 可用性（不含 Key）。
- `POST /api/v1/page-shares/{sid}/progress`：学生端进度；`diagram_states` 键已支持。
- `GET /api/v1/pages/{id}/insights`：所有者学情聚合（`diagram_step_max`/`diagram_completed`）。

**失败语义**

- 视觉不可用/超预算/低置信度 → 400，原裁剪与区域不变，`vision_calls` 已计次数不回退。
- 校验失败（重复节点 id、nodes>40 等）→ 直接拒绝，不写库。
- 转译中并发编辑 → 409 + `error.details.revision` 供前端刷新重试。

**回归**

```bash
# 真实课件回归（需 dev 栈在跑）
python verify/living-p3-regression.py            # 报告 → verify/living-p3-report.json

# 后端/前端/E2E
cd backend && python -m pytest tests/test_living_diagram.py tests/test_living_regions.py -q
cd frontend && npm test && npm run typecheck && npm run build
E2E_BASE_URL=http://localhost:5173 npx playwright test -c e2e/playwright.config.ts --workers=1 living-diagram living-region-interactive living-phase0
```

**开发栈注意**

- `start-dev.ps1` 只管理自己记录的进程（`verify/dev-*.json` + launch_id + 源指纹）；端口上的陌生进程不会被杀，需先手动确认并结束后重跑脚本。源码变更后需要 `-Restart`（脚本会校验 source_fingerprint）。
- E2E 用 `localhost`（Vite 绑 IPv6 ::1），`E2E_BASE_URL=http://localhost:5173`；并行 worker 会让单进程后端上传超时，用 `--workers=1`。
