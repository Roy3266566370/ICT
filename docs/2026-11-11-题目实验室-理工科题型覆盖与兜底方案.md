# 题目实验室：理工科题型覆盖与兜底方案

- 日期：2026-11-11
- 范围：题目实验室的内容建设；不包含代码实现。
- 目标：用最少的新代码覆盖尽可能多的大学理工科题目；每个题型只做“解析、求解校验、视图”三件套；未覆盖题不阻塞用户，转化为下一轮选题依据。

## 0. 一页结论

- 首批覆盖 13 门课程：高等数学、线性代数、概率论与数理统计、最优化方法、数据结构与算法、计算机组成原理、操作系统、计算机网络、离散数学、大学物理、电路分析、数字逻辑、机器学习/深度学习。
- 后续覆盖：程序设计基础、信号与系统、自动控制原理、数据库系统、编译原理、计算机系统结构、软件工程，以及机械/力学类课程。
- 只保留 12 个题型族 + 1 个兜底族；新增课程通过“课程 → 题型族”映射完成，不新增专用页面。
- 每个题型族只实现一套“解析、求解校验、视图”能力；课程差异放在题型配置和内容包中。
- 新增的通用视图只做 5 个：表格、真值表/时序波形、图示标注、代码轨迹、SQL 结果表。它们是一次性工程，可服务多门课程。
- 未覆盖题统一进入“收录 + LLM 讲解”兜底：保留原题、给出带不确定标注的讲解，不自动判分；后台聚类记录，重复出现且需求足够时，才晋级为新题型或新引擎。

## 1. 方法与优先级

### 1.1 依据

优先级参考三类公开信息，避免凭感觉排期：

1. 全国计算机考研 408 大纲：数据结构 45 分、计算机组成原理 45 分、操作系统 35 分、计算机网络 25 分；单选 40 题 80 分 + 综合应用 70 分。
2. 考研数学一大纲：高等数学约 56%、线性代数约 22%、概率论与数理统计约 22%。
3. 国内高校计算机、电子信息、自动化等专业常见培养方案中的核心课程。

说明：本方案给的是**建议优先级**，不是精确考频。正式建设每个题型前，应抽取近 5 年公开真题/教材习题 5～10 道复核；不编造频率数字。

### 1.2 优先级定义

| 级别 | 判定 | 处理 |
|---|---|---|
| P0 | 考纲必考或近年高频，且能复用现有引擎或通用原语 | 首批建设，必须有 3 道回归样题 |
| P1 | 高频但需要 1 个新的通用视图或评估器 | 第二批建设，先做视图原语再批量录入 |
| P2 | 低频、综合题或需要新领域引擎 | 暂不承诺自动求解，先走兜底 |
| P3 | 证明、实验设计、开放论述 | 不自动判分，人工/AI 辅助 |

### 1.3 “覆盖”的判定

一个题型算“已覆盖”，必须同时满足：

- 能从文字/图片/PDF 中稳定解析出题干、已知量、未知量、单位、图表和题型；
- 有确定性求解器或明确的答案评估器，能给出可复现的正确性判断；
- 有可复用的交互视图，学生能作答并获得反馈；
- 有 3 道回归样题（典型、边界、异常/不支持）持续通过；
- 不支持时能明确降级，而不是误判、编造条件或假装已求解。

只有内容、没有自动校验，不算覆盖；只有求解器、没有视图和答题闭环，不算覆盖。

### 2.2 为什么首批选这些

- 408 四门课在计算机考研中权重最高，而且大部分题目可落进数值、表格、顺序、图四类通用能力。
- 数学一的三门课与现有微积分、优化、线性代数能力直接对应，复用率最高。
- 大学物理、电路、数字逻辑是工科共同基础，题型重复度高，一次视图建设可覆盖多专业。
- 机器学习/深度学习已有前向、反向、梯度下降的确定性引擎，属于高复用内容。

### 3.2 三件套的统一规范

#### 解析

- 输出统一结构：题干、已知量、未知量、单位、约束、图表、题型族、置信度、来源；
- 关键条件缺失时生成“阻塞问题”，不得猜测后求解；
- 原题文本、页码、图片始终保留，解析结果可人工修正；
- 新学科优先用“结构化抽取 + 人工确认”，不要为每个学科写一套正则。

#### 求解校验

- 优先复用已有确定性引擎；没有引擎时，用公式/答案规范做评估；
- 每个 P0 题型至少有一条独立校验：量纲、位数、边界、代入回验、守恒量或第二算法；
- 结果包含精确值、近似值、容差和单位；整数/浮点/分数统一口径；
- 不支持时明确返回“无法确定”，不能输出看似合理的假答案。

#### 视图

- 视图只引用已批准的通用原语，不为单题写 React 组件；
- 移动端必须可操作；矩阵、表格、序列在窄屏改为纵向布局；
- 图形与答案输入共享同一份参数，避免“图上是一个数、判题是另一个数”；
- 新增视图必须至少服务两门课程，否则暂缓。

### 3.3 Definition of Done

每个题型建设完成必须交付：

1. 解析规范：输入样例、字段、阻塞条件；
2. 求解/校验规范：引擎或评估器、容差、单位、边界；
3. 视图规范：使用的原语、移动端行为；
4. 3 道回归样题：典型、边界、异常/不支持；
5. 失败降级：解析失败或引擎不可用时，走兜底而不是报错白屏；
6. 内容元数据：课程、知识点、难度、来源、审核状态。

## 4. 分课程题型清单与优先级

下面的“族”对应第 3 节；“复用”优先指已有引擎或通用视图，不把已归档的 `backend/app/engines/*` 算作主链路能力。

### 4.1 高等数学

- **P0 极限与连续（N/X）**：解析函数、趋近点、左右极限；SymPy 求极限并做数值逼近复核；复用公式输入与函数曲线。引擎：符号计算。
- **P0 导数与微分（X/F）**：解析函数与求导点；符号求导 + 差商近似复核；复用导数视图与切线。引擎：`labs/solvers.py` calculus。
- **P0 不定积分/定积分（X/N/F）**：解析被积函数、上下限、变量；SymPy 求原函数/定值，黎曼和数值复核；复用曲线 + 黎曼矩形。引擎：calculus。
- **P0 二重积分/极坐标（N/X/S/F）**：解析区域、被积函数、积分次序；符号/数值求值 + 区域面积校验；复用区域图和数值输入。部分需新增区域视图。
- **P1 级数敛散性（C/X/N）**：解析通项、起点；判别法选择 + 部分和趋势图；新增级数评估器和部分和视图。
- **P1 微分方程（X/F）**：解析阶数、初值、方程；SymPy `dsolve` + 数值解复核；复用曲线视图。
- **P1 多元函数极值与条件极值（S/X/N）**：解析目标函数、约束、驻点；复用优化引擎 + 完整驻点分析（`exam_math.py`）。
- **P2 曲线/曲面积分（N/X/F）**：需新增参数化区域与积分视图。
- **P3 中值定理/不等式证明**：走 Q 兜底，不自动判分。

### 4.2 线性代数

- **P0 行列式计算（M/N）**：解析矩阵；行变换轨迹 + 主元乘积；复用矩阵网格。引擎：`labs/linalg.py`。
- **P0 矩阵运算/逆/秩（M）**：解析矩阵与运算；复用消元/增广矩阵轨迹；答案支持矩阵输入。
- **P0 线性方程组（M）**：解析 Ax=b；高斯消元、主元、回代；复用矩阵与逐步轨迹。
- **P0 向量组线性相关性（C/M）**：解析向量组；秩与行列式判定；复用选择/矩阵输入。
- **P1 特征值/特征向量（M/N）**：当前引擎未覆盖，需新增特征多项式与数值校验；视图复用矩阵 + 向量图。
- **P1 二次型/正定性（C/M）**：解析二次型矩阵；顺序主子式/特征值判定；复用选择与矩阵。
- **P2 相似对角化/线性空间证明**：部分走 Q 兜底。

### 4.3 概率论与数理统计

- **P0 古典概型/条件概率/全概率/贝叶斯（N/X）**：解析事件、样本空间、条件；公式求值 + 枚举复核；复用数值/公式输入。
- **P0 一维随机变量与数字特征（N/F）**：解析分布/密度、期望方差；符号积分 + 数值复核；复用分布图（需新增）。
- **P0 二维分布/协方差/相关系数（N/M）**：解析联合分布或样本；矩阵计算；复用矩阵/表格。
- **P0 参数估计（X/N）**：矩估计/最大似然；符号推导 + 数值代入；复用公式输入。
- **P0 假设检验（C/N）**：解析原假设、统计量、显著性水平；临界值/ p 值计算 + 选项判断。
- **P1 中心极限定理/大数定律（C/N）**：概念选择 + 数值模拟曲线；复用选择与分布图。
- **P1 随机变量函数分布（X/F）**：需新增变量变换与分布图。

说明：概率统计目前没有专用引擎，先以数值/符号评估器 + 分布图覆盖，暂不承诺复杂证明。

### 4.4 最优化方法

- **P0 梯度下降（S/N）**：解析目标函数、初始点、学习率、迭代数；复用优化引擎与轨迹视图。
- **P0 无约束极值/驻点/Hessian（S/X/N）**：复用 `solvers.py` 与 `exam_math.py` 的完整驻点分析。
- **P1 约束极值/拉格朗日乘子（X/N/S）**：解析约束；符号求驻点 + 数值复核；复用曲线/等高线。
- **P1 线性规划/单纯形（T/N/S）**：解析约束与目标；单纯形表轨迹 + 顶点验证；新增表格与可行域视图。
- **P1 一维搜索/牛顿法（S/N）**：复用迭代引擎，新增收敛曲线。
- **P2 整数规划/动态规划**：先走兜底，后补专用表。

### 4.5 数据结构与算法

- **P0 线性表/栈/队列（O/K）**：解析操作序列；逐步执行 + 状态比对；复用序列/代码轨迹视图。
- **P0 二叉树遍历/构造（G/O）**：解析节点关系或遍历序列；复用图/树视图，新增构造校验。
- **P0 图 BFS/DFS/最短路（G/O）**：BFS 直接复用现有引擎；DFS/最短路按同一轨迹模型扩展。
- **P0 排序过程/堆调整（O/S）**：复用堆引擎；排序逐步状态新增通用序列轨迹。
- **P0 查找/哈希（N/O）**：解析表长、关键字、冲突策略；计算探测序列 + 命中率校验。
- **P0 复杂度分析（C/N）**：选择/数值；代码片段计数校验。
- **P1 平衡树/红黑树（G/O）**：新增树旋转轨迹。
- **P1 动态规划/贪心/回溯（T/K/O）**：新增表格或代码轨迹；先覆盖经典模型。

### 4.6 计算机组成原理（408，45 分）

- **P0 数据表示/补码/浮点（N/M）**：解析位宽、编码、运算；位级计算 + 十进制回验；复用数值/矩阵网格。
- **P0 定点/浮点运算与 ALU（N）**：逐步运算 + 溢出/舍入校验；复用数值与步骤视图。
- **P0 存储系统/Cache 映射/命中率（N/T）**：解析地址位宽、块大小、相联度、访问序列；计算 tag/index/offset 与命中率，位数守恒校验；复用数值 + 新增表格。
- **P0 指令格式/寻址方式（N/T）**：解析指令字段；位域拆分 + 地址计算；复用表格。

## 5. 回归样题库

### 5.1 规则

- 每个题型族至少 3 道：典型题、边界题、异常/不支持题；
- 每道样题记录：输入原文、期望解析字段、期望答案/容差、期望视图元素、失败降级行为；
- 后端求解与前端视图都要进入回归，不能只测数值；
- P0 题型的 3 道样题必须来自公开真题/教材习题的改写，避免只测自造简单题；
- 题型升级时先加样题，再改实现。

### 5.2 样题示例（可直接作为首批 fixture）

#### N 数值计算

1. 计算 `∫_0^2 x² dx`；期望 `8/3`；容差 `1e-6`；视图检查：函数曲线 + 黎曼矩形。
2. 指令 A 2 条各 4 周期，B 1 条 3 周期，C 1 条 5 周期，求 CPI；期望 `4.0`；视图检查：周期分解柱状图。
3. `192.168.1.0/26` 的可用主机数；期望 `62`；视图检查：地址位表。

#### X 符号表达式

1. 求 `d/dx(x³e^x)`；期望 `x²e^x(x+3)`；用符号等价校验；视图检查：导数曲线。
2. 求 `∫ x cos x dx`；期望 `x sin x + cos x + C`；视图检查：原函数族曲线。
3. 化简 `A'B + AB'`；期望 `A⊕B`；用真值表等价校验；视图检查：逻辑表达式。

#### C 选择判断

1. 直接映射 Cache 在什么情况下发生冲突；期望：主存块号映射到同一 Cache 行；视图检查：选项与解析。
2. 流水线中“后一条指令需要前一条指令的结果”属于什么冒险；期望：数据冒险；视图检查：选项。
3. TCP 三次握手的核心目的；期望：同步序号并确认双方收发能力；视图检查：选项。

#### O 顺序/步骤

1. 对边 `A-B, A-C, B-D, C-D, D-E` 从 A 做 BFS；期望顺序 `A B C D E`；视图检查：队列与访问序列。
2. 3 个物理块，访问串 `1,2,3,1,4,2`，LRU 缺页次数；期望 `5`；视图检查：帧状态表。
3. 生产者-消费者使用 `empty/full` 信号量，写出正确 PV 顺序；期望：`P(empty) → put → V(full) → P(full) → get → V(empty)`；视图检查：信号量变化。

#### M 矩阵/向量

1. 求 `[[1,2],[3,4]]` 的逆；期望 `[[-2,1],[1.5,-0.5]]`；视图检查：增广矩阵消元轨迹。
2. 解 `x+y=3, 2x-y=0`；期望 `x=1, y=2`；视图检查：主元与回代。
3. 计算 `[[1,2],[3,4]]·[[0,1],[1,0]]`；期望 `[[2,1],[4,3]]`；视图检查：逐元素乘法。

#### T 表格填空

1. 5 段流水线执行 3 条指令，填写每条指令的 IF/ID/EX/MEM/WB 周期；视图检查：时序表。
2. 给定页表，填写虚拟页到物理帧的映射与缺页项；视图检查：页表网格。
3. 给定 `192.168.1.0/24` 与 4 个子网需求，填写网络地址、广播地址、可用范围；视图检查：子网表。

#### G 图/树/自动机

1. 对给定图从 A 做 BFS，填写父节点与层号；期望与引擎轨迹一致；视图检查：BFS 树。
2. 求 A 到 E 的最短路径与距离；视图检查：路径高亮。
3. 依次插入 `5,3,7,2` 到 B+ 树，填写叶子节点顺序；视图检查：树结构。

#### S 参数仿真

1. `f(x)=(x-3)²`，`x0=0`，学习率 `0.1`，求前两步；期望 `x1=0.6, x2=1.08`；视图检查：迭代轨迹。
2. 抛体 `v0=10 m/s, g=9.8`，求最大射程对应角度；期望 `45°`，射程约 `10.2 m`；视图检查：轨迹仪。
3. RC 电路 `R=1kΩ, C=1µF`，求 `5τ` 时电容电压相对终值的比例；期望约 `99.3%`；视图检查：暂态曲线。

#### F 函数/曲线/系统响应

1. 画 `f(x)=x³-3x`，标出零点与极值；期望零点 `-√3,0,√3`，极值点 `±1`；视图检查：曲线与标注。
2. 一阶系统 Bode 幅频曲线在远高于转折频率处的斜率；期望 `-20 dB/dec`；视图检查：Bode 图。
3. 标准正态分布 `N(0,1)` 的 68-95-99.7 区间；视图检查：分布阴影。

#### L 逻辑/时序

1. 全加器真值表；期望 Sum/Carry 与标准一致；视图检查：真值表。
2. SR 锁存器在 S/R 变化下的波形；期望：置位、复位、保持；视图检查：波形。
3. 3 位二进制计数器状态序列；期望 `000→001→…→111→000`；视图检查：状态表 + 波形。

#### D 图示标注

1. 标注 CPU 数据通路中的 PC、IR、ALU、寄存器堆、MAR、MDR；视图检查：标注图。
2. 标注 Cache 地址中的 tag/index/offset 位段；视图检查：位段图。
3. 标注闭环控制系统中的控制器、被控对象、反馈环节；视图检查：框图。

#### K 代码/轨迹

1. 给出 C 循环，预测输出；期望输出值；视图检查：变量轨迹。
2. 给出 5 条汇编指令，填写执行后寄存器值；视图检查：寄存器表。
3. 给出只读 SQL 与样例表，填写查询结果；视图检查：结果表。

#### Q 证明/开放

1. 证明题：只给参考提纲与评分点，不自动判分。
2. 实验设计：按评分量规给出检查项，人工确认。
3. 开放论述：LLM 只做讲解与追问，不标记“正确”。

## 6. 未覆盖题的兜底闭环

### 6.2 记录字段

每个未覆盖题至少记录：

- 指纹：文本归一化哈希、图片感知哈希；
- 来源：文件类型、页数、是否 OCR、是否含公式/图表；
- 分类猜测：课程、题型族、关键词、置信度；
- 用户意图与反馈：想求什么、是否满意、是否重复上传；
- 频次：首次/最近出现时间、独立用户数、重复次数；
- 处理结果：仅讲解、人工补充题型、晋级为新题型；
- 隐私与版权标记：是否允许用于内容建设。

### 6.3 管理员侧：每周收件箱

- 按“独立用户数 × 重复次数”排序，先解决真实高频需求；
- 相似题聚类，避免为同一模式重复建题型；
- 一键把样例题转为“题型包草稿”：补解析、答案规范、视图、3 道回归样题；
- 发布前自动跑回归；通过后进入正式覆盖矩阵；
- 公开“最近新增题型”，让用户知道反馈被采纳。

### 6.4 晋级规则

一个未覆盖模式晋级为新题型/新引擎，建议满足任一条件：

- 近 30 天独立用户数达到阈值，且重复出现；
- 属于 P0 考纲内容，即使当前量少也要补齐；
- 现有题型族可覆盖 80% 以上，只差一个通用视图；
- 有可控的确定性校验方案，而不是只能靠 LLM。

不满足条件的题继续保留在兜底，不急着写代码。

### 6.5 红线

- 不把 LLM 生成的答案当作自动判分依据；
- 不为单个题目写专用页面；
- 不因为“题型少”而删掉原题内容；
- 不在没有回归样题的情况下发布新题型；
- 不把用户上传内容用于训练/展示，除非获得明确授权。

## 7. 引擎复用与新增边界

### 7.1 可直接复用

| 能力 | 位置 | 可服务 |
|---|---|---|
| 微积分求解/几何/法线/极值 | `backend/app/labs/solvers.py`、`exam_math.py` | 高数、线代（部分）、优化 |
| 梯度下降/无约束优化 | `backend/app/labs/solvers.py` | 最优化、机器学习、物理参数题 |
| BFS 轨迹 | `backend/app/labs/solvers.py` | 数据结构、离散数学、网络路由 |
| 堆删除/下滤 | `backend/app/labs/heap.py` | 数据结构、算法 |
| 线性方程组/行列式/逆/矩阵乘法 | `backend/app/labs/linalg.py` | 线代、电路、计组 |
| MLP 前向/反向/训练 | `backend/app/labs/solvers.py` | 深度学习、机器学习 |
| 数学输入/判题 | `frontend/src/components/labs/AttemptMathInput.tsx`、`assistant.py` | N/X/C/O/M 等 |
| 交互画布 | `frontend/src/components/labs/LabCanvas.tsx`、`HeapCanvas.tsx`、`ispec/*` | S/F/G/M/T/D |

注意：`backend/app/engines/bfs.py`、`budget.py`、`force.py`、`matrix.py` 头部已标注 legacy，不再参与主链路；新题型不要把它们当作现成主链路引擎。

### 7.2 只做一次的新增通用能力

| 新能力 | 解锁课程 | 优先级 |
|---|---|---|
| 表格填空视图 | 计组、OS、网络、数据库、概率统计 | 高 |
| 真值表/时序波形 | 数字逻辑、计组、离散数学 | 高 |
| 图示标注层 | 计组、电路、控制、物理 | 中 |
| 代码/步骤轨迹 | 程序设计、编译、OS、算法 | 中 |
| SQL 只读结果表 | 数据库 | 中 |
| 概率分布图 | 概率统计 | 中 |
| 频域/根轨迹图 | 信号、控制 | 低（后续） |

### 7.3 什么情况才新增领域引擎

- 该题型是 P0 高频；
- 现有通用题型无法给出可信校验；
- 有明确的确定性算法和独立校验方式；
- 至少 3 门课程或 30 道题会复用；
- 有 3 道样题和边界测试。

否则优先用“数值/符号 + 表格/曲线 + 人工审核”的通用方案。

## 8. 迭代计划与指标

### 8.1 批次

- 第 1 批（先行）：高数、线代、概率统计、最优化、数据结构、计组、OS、网络、离散数学、大学物理、电路、数字逻辑、机器学习。先把已有引擎和 408 高频题跑通。
- 第 2 批：程序设计（代码轨迹）、信号与系统、自动控制、数据库。
- 第 3 批：编译原理、计算机系统结构、数字信号处理、通信原理。
- 第 4 批：机械/力学及其它专业，先收题再评估。

### 8.2 指标

- P0 题型覆盖率（按课程和知识点）；
- 回归样题通过率（解析、答案、视图三部分分开统计）；
- 未覆盖题的兜底率、重复出现率、独立用户数；
- 新题型从“收件箱”到“上线”的周期；
- 误判/编造条件的事件数，目标为 0；
- 每题平均维护成本（代码改动次数）。

## 9. 风险与未验证

- 考频排序需要真实真题复核，本方案只给结构性优先级；
- 概率统计、电路、信号、控制、数据库、编译等目前没有完整专用引擎，首轮只能覆盖数值/符号/表格/选择类题目；
- 表格、波形、标注、代码轨迹是新增通用视图，需要一次性工程投入；
- LLM 讲解存在错误风险，必须标注“未校验”，且不能作为自动判分依据；
- 题库内容涉及教材/真题版权，录入前需确认来源与授权；
- 服务端判题与答案下发的安全改造不在本方案实现范围内，正式题库前需单独决策。
